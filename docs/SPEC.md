# 仕様 v0.1 — 設計初版

更新日: 2026-11-03。以下の動的な機能は目標仕様であり、実装済みではない。

## 目的と境界

開発計画を「利用者に何が変わるか → どう実現するか → 根拠とコード」の順に読めるようにする。回答を正本へ記録するときに、提案・判断・実行の違いが失われないことを優先する。

独立した開発補助ツールとして作る。既存アプリのランタイムに埋め込まず、保存データの移行も行わない。アカウント、MCPサーバー、課金、AIモデルAPIは初期実装に含めない。

## 画面契約

- 最初に目的、計画の版、現在の状態、未確認事項を見せる。
- 1項目1主張を基本とし、必要なところだけ詳細を開く。
- 各主張に事実・推論・提案・未確認のラベルと出典を持たせる。
- 「要点 / 詳細 / 出典」など意味のある見出しにし、技術知識を前提にしない。
- 判断は未回答から始める。おすすめの表示があっても選択済みにはしない。
- コピーやJSON保存は明示操作で行う。外部送信は行わない。
- 入力受付、ブラウザー内保存、ファイル書出し、正本へ反映済みを別状態として表示する。
- 未保存・容量不足・保存拒否・破損・古い版への回答を正常保存として扱わない。
- 編集内容を失う操作は、変更対象と影響を具体的に説明する。

## 見た目

画面見本の数値はこのツール専用であり、既存アプリの確定値ではない。

| 役割 | 初版の値 |
| --- | --- |
| 本文 | システム日本語フォント、16px、行高1.7 |
| 補足 | 13–14px |
| ページ余白 | 小画面16px / 広い画面32px |
| 面の角丸 | 18px |
| 操作領域 | 44 CSS px以上を初期目標 |
| 明るい背景 / 文字 | #F5F7F8 / #263641 |
| 暗い背景 / 文字 | #151E24 / #E8F0F4 |
| 選択面 / 文字（明） | #E3F0F6 / #214F68 |
| 選択面 / 文字（暗） | #263F4C / #E8F0F4 |

文字と面を必ず対で定義する。色だけで状態を伝えずラベルを併記する。強い光沢や影を増やすより、整列・余白・読みやすさを優先する。

## 受入条件

1. 日本語の通常文を英語の語数・動詞判定で誤って失敗にしない。
2. 320/390/1280px、明暗、長文、詳細展開で主要操作と本文が読める。
3. タッチとキーボードで開閉・選択・回答確認ができる。固定操作が本文を覆い続けない。
4. 未回答、保留、修正依頼、明示的な選択を往復しても区別できる。
5. 再読込後の回答復元、保存禁止時の説明、JSON書出し→読戻しで内容が一致する。
6. 同じ計画の別版・別プロジェクトへ回答が混ざらない。
7. Markdownの出典・ハッシュ・計画版を保持し、古い回答の反映を止められる。
8. HTMLやJSONへ入力されたタグ・スクリプト・危険URLが実行されない。
9. 初期運用ではネットワーク送信ゼロ。正本への書込は別の明示的な段階である。
10. ホスト認識とSkill実行、デスクトップ表示、iPhone Safariはそれぞれ別に結果を記録する。
