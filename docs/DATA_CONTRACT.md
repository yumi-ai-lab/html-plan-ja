# データとOKFの接続契約

本書は本ツール独自の接続設計であり、OKF公式の追加仕様や認証を意味しない。JSON Schemaは草案で、既存の保存形式を置き換えない。

## 正本と派生物

| データ | 役割 | 書込主体 |
| --- | --- | --- |
| 既存のMarkdown・メタデータ | 正本 | 既存の知識管理手順 |
| plan.json | 対象を限定した、版付きの表示用スナップショット | 今後の変換器 |
| HTML | 人が確認するための派生表示 | 今後の生成器 |
| response.json / Markdown | 利用者が入力した回答 | 今後の回答UI |
| C記録 | 依頼・判断・その時の対処の経緯 | 内容を確認した記録処理 |
| F記録 | 実際に行ったことと確認結果 | 実行後の記録処理 |

C/Fは導入先の呼称に合わせて写像する。回答しただけでFの完了を作らない。既存ファイルを開いただけでも更新しない。

## 識別と状態

- `schemaVersion`: 本ツールの形式の版。
- `projectId + planId + revision`: 回答の対象を特定する。localStorageも同じ組合せと形式版で名前空間を分ける。
- `source.path + sha256`: 読んだ正本とその時点の内容。公開物では個人の絶対パスを使わない。
- `claim.id`: 主張ID。事実 / 推論 / 提案 / 未確認と、出典IDを別々に持つ。
- `decision.id`: 質問ID。候補IDを持ち、回答の既定値はnull。
- `answer.status`: unanswered / selected / deferred / needs-change。未回答と既定値の採用を混ぜない。
- `answer.reviewedAt`: 明示的な回答操作の日時。未回答ならnull。選択解除時の履歴は将来別のイベントとして扱う。
- `conversationRefs` / `factRefs`: 既存の二つの時間軸への参照。実体の存在確認なしに正式IDを採番しない。

## 回答取り込み時に必須の確認

JSONの構文、バージョン、サイズ、ID重複、質問・選択肢の存在、回答状態と選択値の整合を検査する。計画版が違えば自動反映せず、差分を提示する。取消・再回答は過去の事実を消さず訂正参照として記録する。

文章やコメントはデータである。シェル命令・実装指示・追加権限へ直接変換しない。HTMLはtextContent相当で描画し、Markdown生成時も引用と本文を区別する。ファイル参照は許可されたルートの配下だけに限定し、シンボリックリンク・相対脱出・秘密ファイルの同梱を防ぐ。

## 持ち運び

初期の完成範囲は「計画と回答を読む・確認するための持ち運び」。アプリデータの復元、画像実体、外部AIの即時接続は含めない。画像は初期サンプルに含めず、将来は出典・権利・サイズ制限とともに設計する。

自動同期は行わず、元の内容が変わった場合は再生成して別revisionにする。生成済みHTMLの内容を、現在の正本と同じであると仮定しない。
